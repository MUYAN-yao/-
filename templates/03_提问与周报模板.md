# 怎样提问、怎样汇报

你不需要把所有问题都独自解决后才提问。好的提问是让别人能快速定位事实与需要作出的决定，而不是展示“我已经很努力”。

## 提问模板

**问题标题：** 用一句话说明哪里不清楚，例如“重算 CNM 的最大哨兵是否应该逐次变化？”

1. **我在解决什么：** 当前任务、运行命令或正在读的函数/段落。
2. **我看到了什么：** 精确数值、错误信息、文件位置；不要只说“跑不通”或“有问题”。
3. **我的预期是什么：** 依据哪条协议、参考结果或代码逻辑。
4. **我已检查什么：** 输入哈希、数组长度、候选名称、环境版本等；附简短证据。
5. **我的暂时解释：** 可以给出两个可能解释，并标明不确定性。
6. **希望你决定什么：** 例如确认解释、选择协议约定，或批准一个明确范围的后续检查。

粘贴报错前检查是否含账号、密钥、访问令牌或未授权数据。代码和报错可提供最小必要片段；不要把整个数据包上传到聊天工具。

### 一个好的例子

> 我在解释 donor 映射。代码把视频 ID 哈希排序后按 7、19 等数值循环取其他视频，因此我认为它不是把同一条曲线移动 7 帧。之后才对 donor 曲线按归一化进度插值到目标长度。我的理解是否正确？如果正确，我会在报告中使用“视频索引位移”，不写“时间偏移”。

### 哪些情况不要自行尝试“修好”

- 输入与协议哈希不一致、预测/标签数量不一致、固定对齐不成立。
- 需要改门槛、改种子、减 donor、删候选或删样本才能“通过”。
- 想新增数据、训练模型、占用服务器或把材料上传 AI。
- 发现不利结果，担心影响论文而想换一个版本报告。
- 想运行尚未获准的第二阶段网格敏感性分析。

这些情况应保留证据并提问。环境安装、路径拼写等普通问题可先按材料排查，但不要因此修改科学协议。若长时间卡住，及时报告，不必等到周报。

## 每周简报（建议一页以内）

**日期 / 姓名 / 本周可投入与实际投入：**

**一句话进展：** 本周查清了什么，而不是运行了多少次。

| 科学问题 | 本周证据与文件 | 当前判断 | 仍不确定什么 |
|---|---|---|---|
|  |  |  |  |

**已完成交付：** 写出结果表、代码版本、记录和说明的位置；尚未完成不要写成已完成。

**负结果与异常：** 包括差异、失败和与原先预期不符的观察。

**本周真正学会的一件事：** 用自己的话说明，例如“为什么 CNM 不能固定扣一个哨兵”。

**AI 帮了什么、我核验了什么：** 区分生成代码、理解代码和验证科学判断。不能仅写“AI 已检查”。

**需要导师作出的决定：** 一至两个清楚的问题；若无则写“无”。

**下阶段最小计划：** 一个能回答具体问题的工作单元，注明是否已经获得范围确认。

## 讨论前的五分钟准备

准备不依赖 AI 代答地讲清：问题是什么、对照是什么、一个关键数字怎么算、证据支持什么、什么还不知道。可以查看自己的笔记，不要求背术语。

如果你认为导师或现有论文的说法不准确，请带着证据直接指出。这不是“拖慢投稿”，而是减少把错误带进论文的风险。
